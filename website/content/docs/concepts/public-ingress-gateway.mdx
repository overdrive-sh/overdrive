The public ingress gateway lets clients outside the node reach a VM Service over
HTTPS. It runs inside `overdrive serve`. It terminates TLS 1.3 on TCP/443,
routes each request by hostname and path to a Service you deployed, and forwards
it to a backend over the same mutual-TLS mesh that workloads use between
themselves. The workload speaks plaintext HTTP and holds no certificate.

You enable it with four `serve` flags and declare what it serves with a Route
document. [Expose a service publicly](/docs/how-to/expose-a-service-publicly)
walks through both.

<Callout title="Scope">
	The gateway handles HTTP/1.1 only. It reads certificates
	from files you provide. Issue
	[#57: an embedded ACME client](https://github.com/overdrive-sh/overdrive/issues/57) tracks
	automated certificate issuance, and issue
	[#341: HTTP/2 and gRPC on the public listener](https://github.com/overdrive-sh/overdrive/issues/341)
	tracks HTTP/2.
</Callout>

## What a Route is

A Route maps one exact hostname and a path (matched exactly or as a segment
prefix) to one Service port. It also names the
certified key the gateway presents for that hostname. A certified key is the
certificate chain and private key you give `serve`, under one id.

```toml
[route]
id = "public-api"
hostname = "api.example.com"
path = "/"
path_match = "segment_prefix"
certified_key = "api-origin"

[route.target]
service = "api"
port = 8080
protocol = "tcp"
```

`path_match` is `exact` or `segment_prefix`. The hostname is one exact name, with
no wildcard. A node holds one Route. You declare it with
`overdrive deploy <ROUTE_SPEC>`, which prints whether the Route was `declared`,
`replaced`, or `unchanged`, along with its generation (a content hash) and the
endpoint. See the
[CLI reference](/docs/reference/cli#route-documents) for every field.

## What the client sees

The listener accepts TLS 1.3 only, negotiates ALPN `http/1.1`, and offers AES-GCM
cipher suites only. The `Host` header must match the TLS server name. A mismatch
gets `421`, and a malformed `Host` gets `400`.

| Status | Cause |
| --- | --- |
| 400 | The request is malformed: an unparseable head, ambiguous message framing or an invalid `Host`. |
| 404 | No Route matches the hostname and path. |
| 408 | The request head or body stalled. |
| 413 | The request body exceeds 16 MiB. |
| 421 | `Host` differs from the TLS server name. |
| 431 | The request head is larger than 32 KiB or carries more than 100 headers. |
| 502 | The backend connection failed, or its response broke a limit or was malformed. |
| 503 | The Service has no backend. This is the only 503 the gateway returns. |
| 505 | The request is not HTTP/1.1. |

The gateway makes one attempt to the backend and never retries. A retry could
repeat a request that is not safe to send twice, and its new connection could reach
a different backend. It strips
hop-by-hop headers, adds `Via: 1.1 overdrive`, and replaces any incoming
`Forwarded` and `X-Forwarded-*` headers with a single `Forwarded` header. The
upstream leg carries `Connection: close`.

### Limits and deadlines

| Limit | Value |
| --- | --- |
| Concurrent connections | 128 |
| Request head | 32 KiB, at most 100 headers, otherwise `431` |
| Requests per connection | 100 |
| Request body | 16 MiB, otherwise `413` |
| Response head from the backend | 32 KiB, at most 100 headers, otherwise `502` |
| Response body from the backend | 16 MiB, otherwise `502` for a declared length or an aborted response for a chunked or close-delimited body |
| Handshake, head, backend connect, response head | 5 s each |
| Body no-progress and idle | 30 s each |
| Whole request | 120 s |

You cannot change these limits in this version. Issue
[#353: configurable gateway limits](https://github.com/overdrive-sh/overdrive/issues/353) tracks making them configurable.

## How a request reaches a backend

Backend selection happens in the kernel. A BPF program runs on every `connect()`
the gateway makes (a `cgroup/connect4` program attached to the gateway's cgroup).
It picks a backend from the same Service maps the mesh uses. The gateway therefore
runs no userspace load balancer and keeps no copy of the backend list. The program ignores the `healthy` flag in the backend map. A request
that arrives in the roughly one second after a backend starts, before it listens,
gets `502`.

The gateway then opens a mutual-TLS connection to the backend using its own SVID,
the SPIFFE identity certificate the node issues. That SVID sits in a dedicated slot, separate from the per-allocation SVIDs the
[identity model](/docs/concepts/identity) describes. The handshake pins the exact
peer the BPF selection chose, so the connection reaches the backend the kernel chose
and no other.

A Service that stops keeps its backend in the kernel map. A request to it gets
`502` and never reaches a different peer.

### The data path

The gateway terminates the client's TLS with rustls, then installs kernel TLS on
both legs. It parses request and response heads itself and moves bodies between
the two sockets with `splice(2)`, so body bytes stay in the kernel. The relay uses
an empty pipe of at least 64 KiB for each splice. A smaller pipe loses bytes, as
the [launch post](/blog/public-ingress-gateway) explains. Kernel TLS key updates
are handled through rustls's kernel connection support.

## Certificates

The gateway reads a leaf-first PEM chain of one to eight certificates and one
PKCS#8 private key. The leaf must carry a single DNS name, be valid now, and
match the key. The status endpoint reports each certificate's source as `manual`. A background task
re-reads both files every 30 seconds. A changed, valid pair becomes a new
generation. A missing or invalid pair leaves the last usable generation in place.

## Operating it

Three operator HTTP endpoints sit on the control plane's mTLS listener.

| Endpoint | Purpose |
| --- | --- |
| `POST /v1/routes` | Declare a Route. `overdrive deploy` calls it. |
| `DELETE /v1/routes/{id}` | Withdraw a Route. |
| `GET /v1/gateway/status` | Report whether the gateway is enabled and whether the listener is bound. |

No CLI verb exists for status or withdrawal. When `serve` runs without the gateway
flags, the Route endpoints return `409` with `gateway_disabled` and status reports
`enabled: false`.

Resource use per exchange is bounded. Measured on one host with a Linux 7.0
kernel and counted for the whole `serve` process, an exchange holds nine
descriptors at peak and seven at steady state, so 128 concurrent exchanges hold at
most 1,152. Resident memory grows about 173 KiB per exchange on a base of
0.73 MB, and a test keeps growth at 128 exchanges under 24,405,456 bytes.

## Current limits

- HTTP/1.1 only. Other protocols get `505`.
- No WebSocket or other protocol upgrade. The gateway strips `Upgrade`, and a
  backend's `101` response becomes `502`.
- One Route per node. Issue
  [#352: several Routes and hostnames on one listener](https://github.com/overdrive-sh/overdrive/issues/352) tracks
  lifting this.
- Certificates come from files. Issue
  [#57: an embedded ACME client](https://github.com/overdrive-sh/overdrive/issues/57) tracks
  automated issuance.
