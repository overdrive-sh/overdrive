---
title: Expose a service publicly
description: Start overdrive serve with the gateway flags, write a Route document, and deploy it so a VM Service answers HTTPS requests on a public hostname.
---

This guide exposes a VM Service you already deployed at
`https://<hostname>/`. You give `serve` a certificate and a listen address,
deploy a Route that points the hostname at the Service, and request it with
`curl`. The [public ingress gateway](/docs/concepts/public-ingress-gateway) page
explains what the gateway does with the request.

<Callout title="Prerequisites">
	A running Service from [Deploy a workload](/docs/how-to/deploy-a-workload) with
	a TCP listener, a certificate chain and private key valid for your hostname, and
	a DNS A record from the hostname to the gateway address. Overdrive does not
	create DNS records. The checked-in example at
	`examples/public-ingress-gateway/` runs `serve` as root on a native x86_64
	host. This guide does not establish whether a non-root process can bind port
	443 on your node.
</Callout>

## Prepare the certificate files

The gateway reads two files. Both paths must be absolute.

- The chain is leaf-first PEM with one to eight certificates, at most 1 MiB.
- The key is a single PKCS#8 PEM, at most 64 KiB.
- Each file must be a regular file, not a symlink, owned by the user that runs
  `serve`. The key file must have no group or other permission bits, so use mode
  `0600`.
- The leaf certificate needs exactly one DNS name, must be valid now, and must
  match the key.

A bad file fails `serve` at startup.

## Start the control plane with the gateway

<Steps>
	<Step>
		**Pass all four gateway flags.** The listener address is the host IPv4 the
		gateway binds. The port is always 443.

		```bash
		overdrive serve \
		  --gateway-address 203.0.113.10 \
		  --gateway-certified-key-id api-origin \
		  --gateway-certificate-chain /etc/overdrive/api-chain.pem \
		  --gateway-private-key /etc/overdrive/api-key.pem
		```

		Pass all four or none. A partial set fails with a gateway configuration
		error before `serve` does anything else.
	</Step>
	<Step>
		**Confirm the gateway is enabled.** `GET /v1/gateway/status` on the operator
		mTLS listener reports `enabled`, and `listener_bound` once port 443 is bound.
		The operator listener requires the client certificate and CA pin that `serve`
		wrote to `~/.overdrive/config`. No CLI verb wraps this endpoint, so call it
		with `curl` and those credentials.
	</Step>
</Steps>

## Write and deploy the Route

The Route names the hostname, the path, the certified key id from the flag above,
and the Service port.

```toml
[route]
id = "public-api"
hostname = "api.example.com"
path = "/"
path_match = "segment_prefix"
certified_key = "api-origin"

[route.target]
service = "api"
port = 8080
protocol = "tcp"
```

`certified_key` must equal `--gateway-certified-key-id`. `service` must equal the
id of your deployed Service. Deploy the file:

```bash
overdrive deploy route.toml
```

```text
Route 'public-api' declared.
Generation: <n>
Endpoint: <endpoint>
```

The first line reads `replaced` when you change an existing Route and `unchanged`
when the file matches what the node holds. A node holds one Route. A Route with a
different `id` returns `409`. Withdraw the current one first with
`DELETE /v1/routes/public-api` on the operator listener.

## Make a request

```bash
curl --tlsv1.3 --http1.1 https://api.example.com/
```

To test before DNS exists, pin the address for this one request:

```bash
curl --tlsv1.3 --http1.1 \
  --resolve api.example.com:443:203.0.113.10 https://api.example.com/
```

The URL host, TLS server name, and `Host` header must all be the Route's hostname.

## When it fails

| Symptom | Likely cause |
| --- | --- |
| `404` | The hostname or path matches no Route. |
| `421` | `Host` differs from the TLS server name. |
| `502` right after a Service starts | The backend is not listening yet. The gateway does not wait for health. Retry. |
| `502` for a stopped Service | The Service has no running backend. |
| `503` | The Service has no backend in the kernel map. |
| `409 gateway_disabled` on deploy | `serve` started without the gateway flags. |
