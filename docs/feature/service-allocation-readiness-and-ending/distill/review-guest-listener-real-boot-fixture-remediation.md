**Kind:** DESIGN contradiction after reproduced conformance falsification. **Severity:** blocking. **Affected boundary:** `netns-density-295`'s accepted `fwd_pair` watch-mode `GuestAbort(g)` abstraction, not the D13 guest-listener hooks.

The **accepted `fwd_pair` contract says the opposite for this very projected phase**. The `netns-density-295` feature delta action map says watch-mode `GuestAbort(g)` discards for `unattached`, `ended` and `refused` (`feature-delta.md:10661`), and its T-5 contract repeats that watch-mode unattached discards while accepted-but-unattached `V_g` remains owned by `owner_flows` (`:13660–13664`). The actual `fwd_pair` driver already projects `accepted` into that same `unattached` phase. Its accepted abstraction premise is therefore falsified by the seeded owner trace.

The new model edit changes watch-mode `GuestAbort(g)` from **discard** to `abortSide(..., byRel=true)` for every `unattached` phase (`fwd_pair.qnt:607–621`). That makes the seed pass and matches the known accepted production owner, but it changes an explicit approved action outcome and contradicts the accepted `fwd_pair` scope statement.
