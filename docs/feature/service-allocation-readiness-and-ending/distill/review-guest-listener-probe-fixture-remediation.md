## Shared-board wiring: the guest control session is a real activation prerequisite

The assigned external integration test first failed before setup because `default_staging_root()` did not exist in the disposable `cgroup-default` guest (`.context/step-05-03-wiring-before.log`). After the fixture created that parent, the same 20-second Pass-row oracle remained RED: the production snapshot showed the allocation `Running`, its GuestListeners descriptor and declared TCP/UDP listeners, but no probe row; the beacon had sent no `EXEC`, and `ServerHandle::guest_flow_observation()` showed the leased CID still `Provisioned` with `session: None` (`.context/step-05-03-wiring-owner-diagnostic.log`). This is concrete evidence that a `Running` row alone did not establish probe-runner registration. The production action shim writes Running, then awaits `activate_guest_network`'s control-session requirement before `VmDriver::on_alloc_running` and `EXEC` (`action_shim/mod.rs:2573–2721`). No amount of `LISTEN` input can complete the task while that prerequisite is missing.

The test was moved from the external integration binary to `src/guest_listener_board_wiring_acceptance.rs` under `#[cfg(all(test, feature = "integration-tests"))]` so it can supply the **existing crate-private** `GuestFlowAdapter(SimGuestFlowIo)` driven port. It still calls `run_server(config, adapters)`, submits the Service through `POST /v1/workloads`, reads leased CID/typed launch token from the production guest-owner observation, queues the guest's ordinary `ControlOpen { launch }` preamble, and waits for both the Running row **and the actual `EXEC` beacon reply** before any `LISTEN` line (`guest_listener_board_wiring_acceptance.rs:92–183,252–353`). The simulated control session is guest input at an already existing port; the test does not call `activate_guest_network`, `on_alloc_running`, the board, or the probe task. `TestDataplaneComposer` and `TestGuestDnsFactory` replace driven adapters, while the production `run_server` still composes the shared `GuestListenerBoard` into `VmDriver` and `ProbeRunner` (`lib.rs:3315–3345,3691–3700`). This is Tier-1 production-composition evidence for board sharing, not a hand-installed missing production effect or a claim to cover the real guest/kernel path.

The undeclared TCP line and partial declared set must still write no startup row within the quiet window. The completing UDP line must still write **exactly one `Pass`** row within the bound, observed through `GET /v1/allocs`; the board remains inaccessible to the assertion. The original test's per-test `/// CONTRACT_SHAPE: bounded-change.` survives. The exact test identity moved in the feature-delta, roadmap steps 05-02/05-03 and Metal inventory from the external integration binary to the control-plane lib binary, retaining `integration-tests` and the existing `cgroup-default` group. No new lane, public port, persisted format or expectation runner was added. The final native Metal test passed **1/1** (`.context/step-05-03-wiring-source-local-control-session.log`).

## Restart-authority model: every ServiceLifecycle tick scans the workload

At `QUINT_SEED=0xd18783b`, step 19 wrote `StartupRow(3, "pass")`; step 20 was `SLAnnounceTerminal(1)`. The driver calls the real ServiceLifecycle tick for the **workload target**, hydrates all allocation facts, persists its returned View and dispatches its actions (`quint_restart_authority.rs:400–482,713–720`). `ServiceLifecycleReconciler::reconcile` loops across `actual.allocs`: D6/DG-12 acknowledges terminal predecessors, and B1 emits Stable for any still-Running allocation with startup Pass and no committed Stable (`service_lifecycle.rs:545–636`). The production row for attempt 3 therefore carried `Stable`, while the old model's `SLAnnounceTerminal(1)` changed only attempt 1's membership (`.context/step-05-03-restart-seed-before.log`). This is an exact owner-scope mismatch, not a reason to hide the projected row.

The revised `serviceLifecycleFacts` fold applies the already approved terminal-membership and Stable-eligibility effects to **every** attempt at each ServiceLifecycle action, before the targeted action's own stop/Stable result (`restart_authority.qnt:225–313`). It sets only `ann` and `stable`; it does not change a row class, stop stage, restart budget, terminal claim or author. The guard keeps terminal rows out of Stable and permits a late startup Pass after a failed stop to clear `ann` exactly as D8 pins. The production driver and its row/View/claim/author projections were not changed; the 22 named/random conformance runs continue to compare them.

The same seed next exposed a separate **fault-stimulus** mismatch at `SLLivenessStop(2, "row_write")`: the old generic one-shot `SimObservationStore` write failure was consumed by an earlier `WriteServiceBackendRow`, so the intended `StopAllocation` allocation-lifecycle row write succeeded. A temporary action diagnostic identified that order and was removed. DISTILL added `inject_alloc_lifecycle_write_failure` to the existing Sim observation adapter's test-support scripting and changed only the conformance driver's `row_write` script to call it (`observation_store.rs:184–189,717–731,830–853`; `quint_restart_authority.rs:473–482`). The queued failure is consumed by the next **allocation-lifecycle** write; unrelated backend writes remain real, and the old general injection remains available. It does not change `ObservationStore`, production dispatch or the model's fault meaning. This is DISTILL-owned Sim scripting, not an invented product API or a production failure workaround.

The original seed then passed **1/1** (`.context/step-05-03-restart-seed-after2.log`) and the full restart-authority conformance selection passed **22/22** (`.context/step-05-03-restart-conformance-after.log`).
