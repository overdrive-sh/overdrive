# Full DESIGN review remediation — greenfield D16 shape

Status: **D16-G1 accepted as the scoped current-format consequence of the user's 2026-11-09 greenfield waiver; independently APPROVED at full DESIGN review iteration 4** ([review](review.md)). D13-S1 and D17-S1 were approved by the user on 2026-11-09 (“rest is fine”) and their exact public signatures live in the feature delta. D15's clean-exit row was corrected under accepted D6 and the P-5 exclusion. Independent DISTILL and roadmap validation remain pending.

## User ruling and bounded waiver

The user said:

> "preserve historical bytes" -> what do um ean? we dont need to preserve anything yet. this is greenfield. not used in production. rest is fine

This explicitly waives **historical persisted-byte and backward-read compatibility for this feature's pre-D16 archive shapes**, and the historical nested-type copies, old-to-new conversion chains and historical fixture additions that existed only to supply that compatibility. It does not waive the current `inferred` removal, a coherent current archive and wire shape, the Service/Job lifecycle and readiness invariants, typed errors, the five-carrier inventory, or preservation of pre-existing dirty work. It does not authorize a global reset of the repository's envelope system or alteration of unrelated fixture literals. The previously proposed D16-S1 historical five-carrier migration was **never accepted** and is withdrawn under this ruling.

The full reviewer verified that a raw Service with a sole `GuestListeners` startup descriptor can reach `WorkloadIntentEnvelope::V1` through `Service::from_submit` and `submit_workload` before any probe task runs (`aggregate/mod.rs:412-474,721-722`; `handlers.rs:295-341,475`). This remains an accurate current-code fact. The user's greenfield ruling removes a requirement to decode bytes made by this unfinished feature's earlier checkout; it does not change D14-E2's accepted raw-Service admission or suppress the `GuestListeners` value in the **new** current archive.

## Decision 1 — D16-G1: rebaseline only the five affected current carriers in place

**Exact version policy accepted under the user's quoted greenfield waiver.** D16 removes `inferred` in one cut. Keep the existing envelope names, variants, discriminants, latest aliases and constructor selection. Change the *current* payload layouts in place, because there is no production data to migrate. This is limited to the five already identified carriers; it adds no V2/V3 variant, historical nested type, migration reader, old-to-new conversion, storage table or new wire field.

| Affected carrier | Envelope/version and latest public shape after D16-G1 | Exact change |
|---|---|---|
| Service intent | `WorkloadIntentEnvelope::V1(WorkloadIntentV1)`, tag 0; `WorkloadIntent = WorkloadIntentLatest = WorkloadIntentV1`, `Service = ServiceV1` | `ServiceV1` keeps every existing field and its order. Its `startup_probes`, `readiness_probes` and `liveness_probes` remain `Vec<ProbeDescriptor>`. The same public `ProbeDescriptor` struct loses only `inferred: bool`; `ProbeMechanic` keeps `Tcp`, `Http`, `GuestListeners` in current order (tags 0, 1, 2). Current V1 Service bytes may contain `GuestListeners`; no provenance gate or exclusion is added. |
| Parser-side Service spec | `ServiceSpecEnvelope::V1(ServiceSpecV1)`, tag 0; `ServiceSpec = ServiceSpecLatest = ServiceSpecV1` | `ServiceSpecV1` keeps its fields/order and its three `Vec<ProbeDescriptor>` fields use the same current descriptor without `inferred`. Operator TOML still cannot declare `guest_listeners` (D14-E2). |
| Probe result | `ProbeResultRowEnvelope::{V1(ProbeResultRowV1), V2(ProbeResultRowV2)}`, tags 0 and 1; `ProbeResultRow = ProbeResultRowLatest = ProbeResultRowV2` | Remove `inferred: bool` from **both** existing payload structs. V2 otherwise keeps `alloc_id`, `probe_idx`, `role`, `status`, `last_observed_at_unix_ms`, `run_seq`, `same_status_runs` in current order. V1 keeps its other five fields in current order. The existing V1→V2 conversion still sets `run_seq = FIRST` and `same_status_runs = ONE` and copies the surviving fields; it is not a new historical-inferred migration chain. |
| Allocation status | `AllocStatusRowEnvelope::V1(AllocStatusRowV1)`, tag 0; `AllocStatusRow = AllocStatusRowLatest = AllocStatusRowV1` | The row keeps every field/order. Its `terminal: Option<TerminalCondition>` and nested `last_terminated.terminal` use the current `TerminalCondition::Stable` witness. The same public `ProbeWitness` struct keeps `probe_idx: u32`, `role: String`, `mechanic_summary: String` in order and loses only `inferred: bool`. `LastTerminated` and `TerminalCondition` keep their current names and all other fields/variants. |
| Allocation lifecycle occurrence | `AllocLifecycleOccurrenceRowEnvelope::V1(AllocLifecycleOccurrenceRowV1)`, tag 0; `AllocLifecycleOccurrenceRow = AllocLifecycleOccurrenceRowV1`, `VersionedEnvelope::Latest = AllocLifecycleOccurrenceRowV1` | The occurrence keeps every field/order. Its `terminal: Option<TerminalCondition>` uses the same current `ProbeWitness` without `inferred`. The local store still writes this envelope in `write_alloc_lifecycle_transaction`; it is not omitted merely because the original D16 table missed it. |

`VersionedEnvelope::latest()` and `into_latest()` still select/project the existing latest variants. `known_discriminants()` stays `[0]` for the four V1-only envelopes and `[0, 1]` for `ProbeResultRowEnvelope`; no tag is renumbered. `WorkloadIntentEnvelope::discriminant_offset_from_end()` remains `None`. Existing numeric discriminant offsets for the other affected envelopes are recalculated from the new canonical archive layout and checked against **new current-layout** golden evidence, not guessed. The existing `ProbeResultRowV1` variant and its V1→V2 run-count conversion are retained because they are pre-existing envelope infrastructure; no new historical compatibility types or conversion chains are added.

The new build may reject or reinterpret pre-D16 bytes carrying the same version tag. That is the **only** compatibility weakening, covered by the user's quoted greenfield ruling. Local redb data created by an earlier unfinished checkout is discarded before using the new build, following the repository's existing greenfield single-cut policy (`.claude/rules/development.md` § rkyv schema evolution). No runtime dual-read period or migration is promised. Existing `FIXTURE_V*` **literals are not rewritten**. Historical-byte decode assertions for only these affected carrier layouts cease to gate the changed feature under the waiver; DISTILL/DELIVER provide current-layout golden/roundtrip evidence for all five carriers and keep every unrelated envelope fixture/test unchanged. Test-support placement and exact fixture names are DISTILL's to shape. The current REST/OpenAPI/CLI wire removes `inferred` from `ProbeDescriptor`, probe-result bodies, the Stable witness and render/describe as already accepted; no other wire field or meaning changes.

Because rkyv sizes an archived enum from its largest variant, rebaselining `WorkloadIntentEnvelope::V1` can change pre-D16 bytes even for its Job and Schedule variants, despite their unchanged semantic payloads. `WorkloadIntentV1::spec_digest()` can likewise have a new cross-build baseline, since it hashes archived inner bytes. Those are historical-byte consequences covered by the same explicit waiver; within the new build, two archivals of the same intent must still be byte-identical, and the accepted `put_if_absent` idempotency, kind dispatch and current Job/Schedule behavior remain unchanged. The waiver is not permission to change those current invariants.

**Bounded rollout:** roadmap 05-04 removes `ProbeDescriptor.inferred` and rebaselines the Service intent and Service-spec carrier layouts in one commit while retaining the working default TCP gate. Roadmap 05-05 removes `ProbeResultRow.inferred` and `ProbeWitness.inferred` and rebaselines probe-result, allocation-status and allocation-lifecycle-occurrence layouts in one commit. Each commit updates every directly affected constructor, codec offset and current-layout fixture for its group; neither writes an old nested shape under a new current payload. The existing roadmap step order, DES sequence and final mutation gate are unchanged.

**Minimal alternatives:** appending versions with historical nested types and up-conversion is the withdrawn D16-S1 choice; it spends public API and fixture effort on bytes the user says are not needed. Removing envelope families, renumbering tags or rewriting unrelated fixtures is a broader reset than this feature needs. Retaining `inferred` is D16 option K, rejected by the user. D16-G1 is the smallest current-format change that removes the field everywhere while keeping the five existing carrier families coherent.

## Approved callable signatures and resolved D15 correction

**D13-S1, user-approved “rest is fine”.** `VmDriver::new` takes the shared `Arc<GuestListenerBoard>` as its ninth and last parameter after `BeaconIntake`; the first eight parameters keep their existing types/order. `ReportedListeners::contains(&self, Proto, NonZeroU16) -> bool`, `len(&self) -> usize`, and `is_empty(&self) -> bool` are pinned in the feature delta D13 item 10. No new `Driver` method or board write port is added.

**D17-S1, user-approved “rest is fine”.** `ReconcilerRuntime::broker(&self) -> BrokerDrain<'_>` returns a public guard with a private field, exactly `drain_pending(&mut self, usize, &BTreeSet<TargetResource>, Instant, UnixInstant) -> Vec<(Evaluation, Duration)>`, `next_eligible_at(&self, &BTreeSet<TargetResource>) -> Option<UnixInstant>`, and `counters(&self) -> BrokerCounters`; there is no `submit` or deref escape. `broker_mutex()` is removed and every submit goes through the previously accepted `submit_evaluation` wake path. The feature delta § D17-S1 owns the full signatures.

**D15 correction, no new decision.** The D15 table now distinguishes exit 1 before listener readiness (`EarlyExit` at give-up) from exit 0 (`BackoffExhausted` at give-up), as accepted D6, S-15, ADR-0258 and the user's P-5 exclusion already require. No clean-exit classifier was added.
