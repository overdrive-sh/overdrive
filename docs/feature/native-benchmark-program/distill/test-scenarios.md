# Test scenarios — native-benchmark-program (DISTILL)

Specification only; nothing here is parsed. Executable bodies are Rust tests (`.claude/rules/testing.md`: no `.feature` files). Each test row: scenario | traces | driving port | production owner path | fault stimulus | outcome oracle | lane. Every row carries its **Contract Shape** (`pure-function`, `bounded-change` or `unbounded-preservation`), and every test body carries the same value as a `CONTRACT_SHAPE:` doc-comment line (precedent: `overdrive-testing` and `dns_responder_bind`). Test names are behaviours (`domain-naming.md`). Lanes: **trybuild**, **int-host** (integration, host-pure subprocess), **int-guest** (integration, in a guest group), **xtask** (bootstrap.sh / xtask command line, host-pure). `bench-report` = `cargo bench-report` binary (DDD-1 port 6). "RED" = pending as `#[should_panic(expected = ...)]`; "GREEN" = passes now and guards the contract.

**Ruling (user, 2026-11-17).** The runner's end-to-end run over a real replicate cohort is a benchmark, not a test, and a product test is never `native_launcher` (`testing.md` § "Classify external execution"; DESIGN DDD-9, "Evidence lane"). No nextest test runs the runner over a cohort, and `overdrive-bench-families` keeps no hand-written test. The scenarios that did are in [Benchmark-run evidence](#benchmark-run-evidence-deliver-retained-not-tests) below. In nextest the runner path is covered by the macro-generated smoke tests (one replicate per arm, no timing) and by the record and report tests on crafted records.

Names pinned by DISTILL (OQ-5), used by the evidence scenarios and the crafter: VM metrics `admission_ns`, `vmm_launch_ns`, `guest_ready_ns`, `stable_ns`, `stop_submission_ns`, `shutdown_delivery_ns`, `guest_exit_ns`, `cleanup_calls_ns` (table `host-stages`), `guest_shutdown_handling_ns` (table `guest-stages`); VM profiles `healthy-concurrency-1`, `healthy-concurrency-4`, `cold-cache` (preparation "page cache dropped before each replicate"), `warm-cache` ("image pre-read"), `stop-grace-deadline`; VM notes `cache_state`, `vm_resources`, `concurrency`, `cloud_hypervisor_version`, `host_kernel`. DNS metrics `client_latency_ns` (series), `client_throughput_qps` (table `client-observed`), `resolver_service_ns` (series, `resolver-internal`); DNS profiles `a-record-100-names-1-client`, `aaaa-no-data-100-names-1-client`, `unknown-name-100-names-1-client`, `a-record-10000-names-16-clients`, each `preparation` stating `scheduled-arrival`, qps and seconds. mTLS metrics `connection_establishment_ns`, `handshake_ns`, `first_byte_ns`, `throughput_bytes_per_second`, `tail_latency_ns`, `host_cpu_{user,system,irq,softirq}_ratio`, `memory_bytes`, `socket_count`, `connection_concurrency`, `forward_userspace_cpu_ratio`, `return_splice_cpu_ratio`; profiles `egress`, `ingress`; preparation text names the plaintext baseline and "closed-loop".

Smoke placement of the families (OQ-3, resolved here): connect-hook `guest = "cgroup-default"` (CA-1, already in its declaration); `vm-lifecycle` and `dns-responder` `guest = "cgroup-default"` (they need cgroup v2 and a netns / nested VM, which that group provides); `mtls-path` `guest = "mtls-relay"` (the group the pump-name test already uses). The smoke tests are emitted by the macro from each family's declaration, so they are not hand-authored here; each becomes live in its family's DELIVER step.

## Benchmark-run evidence (DELIVER, retained, not tests)

Each run is `cargo xtask metal run --benchmark <family> [--spike <name>]` under exclusive admission (DDD-9), on the pinned test host. The run prints `OVERDRIVE_METAL_RUN_ID=` and, once its results directory exists and before the canary, `OVERDRIVE_BENCH_RESULT_DIR=<repo-relative path>` (printed for a refused or killed run too); the record and report are pulled with `cargo xtask metal pull <path>` and committed (maintained) or kept under `spike-scratch/<name>/results/` (spike). The observation named for each scenario is read from the retained `record.jsonl` and `report.md`, validated with `bench-report validate`. These are point-in-time receipts, never rerun by CI. Where a scenario's wording is "the runner ...", the observable is the exit status the run printed (`OVERDRIVE_METAL_RUN_COMPLETE ... exit_code=`) plus the retained files.
