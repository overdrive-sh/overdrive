# DESIGN wave decisions: node-local persistent volume (GH #348)

**Status (2026-11-19):** every decision below is approved by the user on the date in its row; ADR-0310 to ADR-0320 and ADR-0334 to ADR-0338 are
Accepted and not yet implemented, apart from the implemented ADR-0073 and ADR-0102, which carry amendment sections. The contracts are in
`../feature-delta.md`; each ADR holds one decision. Scope: all priorities. This file owns the decision table and the limitation table.

**Terms.** The **volume pool** is the node-level LVM setup every VM volume is carved from: the `overdrive-volumes` partition, the physical
volume and the `overdrive` volume group on it, plus the `lvm` tools and device-mapper. One **VM volume** is a single logical volume in the pool.
The pool is not one of Overdrive's internal stores (intent store, observation store).

**Independent re-review of the stuck-VM design (2026-11-23): APPROVED, with five contract-text fixes, applied in place. No ruling is reopened and
no decision changes.**

1. ADR-0352's rejection of the child's own `cgroup.procs` write rests on the window outside the scope and not on accounting: `copy_mm`
   (`kernel/fork.c:2223 @ v7.0`) runs before `cgroup_can_fork` (`:2322`), so `clone3` charges the address-space copy to `serve`'s cgroup too;
   only post-`exec` charges land in the scope. The clause is removed from the ADR and from RB-9; the feature delta states the corrected reason.
2. The launch primitive pins its three paths (feature delta § "A VMM is born inside its scope", items 4 and 5): the launch is one synchronous
   function run in `spawn_blocking`, and the pidfd is wrapped in a guard that kills and hands the pidfd to a reaper on drop, so a dropped
   `create` future never orphans a VMM; parent-side `dup2` sources use `F_DUPFD_CLOEXEC` with a minimum of 3 (`fs/fcntl.c:460-461`,
   `fs/file.c:1498-1504 @ v7.0`); the error pipe is read in `spawn_blocking`, with the delayed end-of-file from a concurrent launch's child
   stated. The stale "four bytes" read is corrected to the five-byte payload. Tests added: cancellation, and closed stdio.
3. The single-remover scan names `CgroupFs::remove_dir` and `remove_dir_all`, lists the allowed callers (`kill_scope` and the adapters' own
   probes, `overdrive-host/src/cgroup_fs.rs:169`), and lists the stale comments rewritten in the same change
   (`overdrive-sim/src/adapters/cgroup_fs.rs:413`, `overdrive-core/src/traits/cgroup_fs.rs:152`).
4. `reserve_leftover` does not `unreachable!` on persisted data: an address outside the prefix or an offset already held is a corrupt row, and
   boot refuses with `ConvergeError::Reclamation` carrying a distinct typed variant, `ReclamationError::CorruptLeftoverRow(CorruptLeftoverRow)`
   (`AddressOutsidePrefix` or `OffsetAlreadyHeld`, each naming the allocation), mapped unchanged by `converge`. `ReclamationError::Host` stays the
   `VmHostState` failure (`rust.md` § "Errors"). Both types are public API of `overdrive-control-plane`; `reserve_leftover` stays crate-internal.
   This is corruption, not a dead VM; ruling 14c is unaffected.
5. `converge` collects the busy signal as `Err(ReclamationError::Host(err))` with `ErrorKind::ResourceBusy` (the ADR-0354 Running case
   included), runs every executor to completion, reserves every busy scope, and only then refuses with the first non-busy error, so no
   scope's reservation is lost. The cost budget of the design is added to the feature delta; model-check times are pending the modeler.

Two choices are made under this design's authority: the `LaunchedChild` guard kills and hands the pidfd to a reaper on drop, and the
single-remover scan's allow-list includes the `CgroupFs` adapters' own probe removals.

**Resolution of the DISTILL gaps in the stuck-VM design (2026-11-24, N3 and N6 of `distill/test-scenarios.md`). Choices within approved
decisions; nothing operator-visible changes and no ruling is reopened.**

1. **Duplicate-owner restart (ADR-0353, no new reason).** The Restart arm applies the Start arm's rule to its successor: no `Pending` row when
   the successor's own row is non-terminal. A duplicate dispatch (`AllocationAlreadyOwned`) then writes no row, ends none, keeps the owner's
   lease and returns `Ok(())` to `finish_restart`. "Duplicate owner after this dispatch wrote `Pending`" is unreachable (a claim is taken only
   after its dispatch wrote `Pending`; rows are never deleted; a launch-ending path releases the claim before returning), so ADR-0355 gains no
   reason and the N-4 ruling holds. DELIVER confirms the release-before-return premise. The R9 test is rearranged by DISTILL to an owner with
   its `Pending` row present; "owner claim, no row" is not produced by `serve` plus `deploy`. Rejected: a terminal reason for a duplicate
   (reaches no real state, adds a persisted variant and fixtures); a driver ownership query before the write (new port surface).
2. **The post-`Running` fail-closed `Failed` row carries the `Running` row's address (ADR-0353 carry table).** The VMM may hold its CID until
   the stop settles (`KilledNotReaped`), and boot reads the address from the newest row. The provision-failure `Failed` row has none to carry.
   `assert_superseding_failed_row` changes to equality.
3. **Test seams: none added.** (a) `RealVmHostState::new` already takes `cgroup_root`; the tempdir tests that need no cgroupfs notification use
   it, and the ordering and mid-wait cases of ADR-0349 are shown on real cgroupfs (the held-scope Tier-3 test). (b) The wrapper is chosen by
   the guest's `PATH` through the execvp-faithful resolution now pinned in item 4 of ADR-0352's contract; a builder would let a test run a
   launch the product never builds. (c) The stand-in hypervisor is a test-compiled Rust program built with the `nested-launch-rustc` guest's
   `rustc`, passed to `with_binary`. Dropped: the uninterruptible-I/O stand-in (S-VOL-T3-12's real held flush covers it), the real core dump
   (a mapping unit test covers it) and a `PermissionDenied` removal (unreachable as root).

**The pool reports a boot reservation as a lease with no launch token (2026-11-24, gap found at step 09-01). A choice within ADR-0350;
nothing an operator observes changes and no ruling is reopened.**

`GuestAddressPool::reserve_leftover` makes a Retiring lease with no `GuestNetworkPlan` and so no launch token, but `lease_observation()`
(QPROJ-2) and `GuestLeaseView { cid, state, launch }` assumed every lease has one. `GuestLeaseView` (a `pub` type of `overdrive-control-plane`, not
core) becomes an enum, `Launched { cid, state, launch }` or `Reserved { cid }`, with `cid()`, `state()` (`Reserved` is Retiring) and
`launch() -> Option<LaunchToken>`; `lease_observation()` keeps listing every lease. A reservation with a launch token, and an Admitted
reservation, are unrepresentable. Production hydration (`GuestAttachmentView::observe`, `GuestAttachmentLease`, `GuestAttachmentObservation` in
`overdrive-core`) already carries no launch token and already reports a reservation Retiring: it does not change. Only tests, conformance drivers
and fixtures read `GuestLeaseView`; those that read the launch token call `launch()`. Contract: feature delta § "Boot proceeds past a stuck VM (RB-4;
ADR-0350)", "How the pool reports a reservation". Rejected: `launch: Option<LaunchToken>` (keeps invalid combinations representable); a
`Reserved` variant of the core `GuestAttachmentLease` (changes core API and every exhaustive match for a distinction no reconciler decision uses);
omitting reservations from `lease_observation` (splits `CidUnique` and the stuck-VM CID checks across two maps).
