# Upstream issues — guest-benchmark-substrate (DISTILL)

Gaps and ambiguities found while authoring, with how each was handled. **No DESIGN gap blocks a test.** Nothing was filled with invented API: where a test needed surface the design does not pin, the test was written against an independent oracle or against only what is pinned, and the point is recorded here. Reconciliation across DISCUSS, DESIGN and DEVOPS: DEVOPS artifacts absent (warning, default Metal matrix); DISCUSS and DESIGN contradictions are the four Changed Assumptions (CA-1 to CA-4), which DESIGN already states and the tests follow; zero unresolved contradictions.

- **U1 (printer surface not pinned): resolved by DISTILL.** DDD-6 pins the console grammar and the parser but named no printer function; the feature-delta now says DISTILL scaffolds the printer beside the parser so one owner holds the grammar. `print_program_return(kernel, clocksource, metric, values) -> String` is scaffolded in `overdrive_testing::guest_app` (inert: prints nothing) and GA1-GA17 print every console through it and read it back with `parse_program_return`; the checksum definition is still pinned by two independent fixed vectors (GA3). It is test-support surface, so it is DISTILL's to shape; the crafter implements it to the grammar in its rustdoc (the end line carries only the metric and the checksum, no count) and may add the program's `forwarding-bench` argv freely.
- **U2 (error variant precision): crafter detail.** `ProgramReturnError` lists `BlockMissing`, `BlockRepeated` and `BlockMalformed` without saying which a begin line without an end line, a non-numeric value or a spliced line is, nor what makes a reading `ReadingMalformed`. The tests pin a variant only where the design is unambiguous (no begin line at all is `BlockMissing`; two blocks `BlockRepeated`; a short or long count `CountMismatch { expected, found }`; a changed value `ChecksumMismatch`; a missing or repeated reading names its key) and assert `Err` where it is not (GA6, GA10, GA11), after proving a control parses so the `Err` is not vacuous. A count mismatch caused by a dropped value may also fail the checksum; GA16 accepts either, since the design does not order the two checks.
- **U3 (report lines with no view): pinned by DESIGN.** A guest record with no `guest_observed` line prints each of the seven observed lines (`vcpus`, `memory mib`, `kernel`, `clocksource`, and one `artifact <key>` line per artifact) as `absent: no replicate returned a guest view`; GP2 already asserts all seven. Original note:  DDD-2 says a record with no `guest_observed` line "prints each observed value as `absent: no replicate returned a guest view`" but also says the artifacts are "one line per artifact". GP2 asserts the three artifact lines, `vcpus`, `memory mib`, `kernel` and `clocksource` each print that phrase. If DESIGN meant one artifacts line, GP2 is the one assertion to change.
- **U4 (validator line number for an ok replicate with no preceding view): crafter detail.** DDD-2's rule is "the first `ok` replicate line of a guest record is preceded by [the `guest_observed` line]". A validator can name either the replicate line or the missing line. GV4 asserts exit 65, the pinned message prefix and that the reason names `guest_observed`, without a line number for the two cases where either is reasonable (the line after the first ok replicate; an ok replicate and no view). Every other case in GV3-GV5 pins its line (1 or 3).
- **U5 (`GuestMemoryMibError` shape): crafter detail.** DDD-4 names the type without its shape. The scaffold is a unit struct; GM2-GM5 only use `is_err()`, `to_string()` on the serde error naming `memory_mib` and equality of the parsed size. DELIVER shapes it.
- **U6 (`retain_console` twice under `smoke`): pinned by DESIGN.** Under `smoke` only the effect is skipped; a guest-substrate precondition failure, the M-1 failure (`Ok` without `report_guest_view`) and a second `retain_console` call fail the replicate exactly as in a real run. GR14-GR16 pin the three, each against a control that passes `smoke`. Original note:  DDD-9 says a second call "is a `ReplicateFailure`" and "under `smoke` nothing is written and `Ok(())` is returned". Whether the second call fails under smoke is not stated; GR13 calls it once.
- **U7 (existing tests replaced).** The behaviour ADR-0325 removes was pinned by tests (the `guest` refusal text and its registry tests, the compile-fail fixture, the closed-vocabulary case). They were rewritten here (list in `test-scenarios.md`) so DELIVER never edits an acceptance body.
- **U8 (the guest family's smoke test and declaration are not DISTILL artifacts).** The declaration does not compile while the registry refuses `guest`, and its smoke test is macro-generated. No scaffold family is added, no hand-written families test exists (the parent's ruling D-1: the families crate keeps no hand-written test). The family, its smoke test and its placement land with its DELIVER step; `placement-lint` is the gate. This is a deliberate gap in the DISTILL-time proof of US-GBS-04 AC (a)/(b), carried by GR13, GT2 and the retained run E-G1.
- **U9 (real-guest scenarios).** Boundary scenarios 2, 4 and 5 at the guest level (no READY, a late READY, a death after READY) and V-C are evidence runs (`test-scenarios.md` E-G3, E-G4, E-G5, E-G7); the design assigns them to the retained Metal run. Their runner-level consequences are GR3-GR5, GR12 and GA7-GA13.
- **U10 (nothing for the orchestrator to amend).** The rule-text edits listed under DESIGN "Rule text the orchestrator edits" (`testing.md`, `.gitignore` for `benchmarks/results/**/artifacts/`) remain as DESIGN left them; no DISTILL change depends on them.
- **U11 (F3: `run_in_guest_program` failure handling, user ruling option (a), 2026-11-19): resolved by DISTILL.** Five guest-placed regression tests (GF1-GF5, `crates/overdrive-testing/tests/integration/guest_program_failures.rs`) replace the earlier no-obligation text. Two cases are not tests, with reasons in `test-scenarios.md` "No-obligation rulings": a READY after the bound is indistinguishable from GF2 at the host half (the bound kills the VMM), and a VMM that does not exit after EXIT cannot be produced deterministically from test support (it needs a VMM stand-in that ignores guest power-off, which is new test-support surface; surfaced for the user, not added).
- **U12 (CIDs for GF1-GF5): crafter note.** The tests use benchmark-band slots 11 to 15, each in its own outer guest, rather than a new band, so `REGISTERED` keeps the six bands GK1 pins. The band's name reads "guest benchmark"; if the user prefers a band per file, that is a registry change plus GK1's count.
- **U13 (the watcher reads the guest console file from `/run`).** The kit does not expose a running guest's console path outside the crate (`live_consoles` is `pub(crate)`), so the test's watcher finds `console.log` under the VMM runtime root by walking `/run`. The kit's runtime layout (`VmRunDir::console_log`) is existing surface; if it moves, the walk is the one line to change. No new API was added for it.
