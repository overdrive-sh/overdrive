## Conventions

- Lanes and placement follow `testing.md` § "Test placement". A test that boots `run_server` takes the `cgroup-default` guest group (never host-pure). Pure sim/core/owner tests are `host_pure`.
- Pending scenarios (DELIVER step not landed) carry the complete executable body and `#[should_panic(expected = "<semantic RED>")]`. The `expected` text is the failing assertion's own message, so a body failing for another reason is not RED. Proven on metal 2026-11-16 (nextest reports the should-panic test as passed only when the panic text matched).
- Names are behaviours; no roadmap step IDs (`domain-naming.md`).
- Contract shape is declared per test (`CONTRACT_SHAPE:` doc line): all slice 01 and 04 tests `bounded-change`; D-11 `pure refusal`; the boot-program test `unbounded-preservation`.
- Faults are injected at existing driven-port seams and production authors the consequence (`testing.md` § "DISTILL — prove composed system behavior"). Disputed terminal states are never seeded.

Notes:
- **AC1's third stimulus, `RunningAllocationWithoutWorkloadAddr`, has no slice 01 test, by contract not by omission.** The condition is a property of the `Running` row (no `workload_addr`; no production path writes one, so it is Tier 1 only). Clearing it is a corrected-row write, and an accepted `alloc_status` write wakes the target through the interest router (edge), today and after DELIVER. The recovery therefore never depends on the pass, so no test can be RED for the pass or discriminate it; a test would pass today and assert only the edge. The typed refusal is already pinned by `crates/overdrive-control-plane/tests/acceptance/service_lifecycle_hydrate.rs:1085` (`HydrateError::RunningAllocationWithoutWorkloadAddr`), and the model's `hydrateErr` outcome covers an evaluation that ends at its hydrate (named run `hydrate_error_recovers_by_pass`, replayed by the conformance driver). Surfaced for the orchestrator: if the user wants a test anyway, it is a GREEN edge regression guard, not a pending RED.
- **Burst admission** (a deploy arriving while a pass has queued every target) is covered by the Quint run `edge_wake_during_burst_is_admitted_after_burst` (replayed by the conformance driver against the production `BrokerDrain`/`EvaluationBroker`: `OneActivePerTarget`, `ActiveWithinCap`, oldest-first) and by the `eval_broker` FIFO tests. - **"A target that has left desired and actual stops being evaluated"** (slice IN): asserted by the containment tests of WK-4, where the `neither` candidate (no intent, no row) must be absent from the set `managed_targets` returns (`workload_lifecycle_manages_every_workload_with_intent_or_an_allocation_row` in `convergence_property/managed_targets_containment.rs`). The pass submits only members of that set, so an absent target is never evaluated.
- **AC6 (seeded invariant).** The slice 01 tests are scripted scenarios on the deterministic `SimClock` with no random source: there is no seed to print, and no existing seeded harness composes `run_server` (the `cargo dst` harness runs `overdrive-sim` invariants over sim components, not the production boot). - AC5 (converged state emits zero non-`Noop`, cost no greater than today's relist) has no separate test here: stability is asserted by the slice 04 property (hydrator today) and the cost figure is V-3 evidence (`spike-scratch/reconciler-resync-cost/evidence/`), a measurement, not a regression test. - `cadence_resync.rs` (`tests/acceptance`) and the router periodic-relist tests in `interest_router.rs` assert items D-1c removes: DELIVER deletes them in the same commit (deletion discipline). They are not coverage for this feature.

### D-20 contract gaps and questions (DISTILL 2026-11-17)

- **B-D20-1 (composition root signature unpinned) — RULED 2026-11-17: `DataplanePorts`, see "Composition wiring obligation".** D-20 says both ports are "wired from the dataplane instance the composition root already builds", but `AppState.dataplane` is `Arc<dyn Dataplane>` and no constructor takes a `ProgrammedServiceView`. Threading the view means a new `AppState` field and a new parameter on `AppState::new` / `new_with_workflow_engine` (about 175 construction sites), or another shape. The shape is a composition-root signature, which the delta must pin. Until then `build_hydration_context` supplies a private inert stand-in, so the hydrator reads `None` for every frontend in a composed node even once its `hydrate_actual` reads the port; the two reboot tests cannot go GREEN without it.
- **B-D20-2 (IPv6 backend: refused or skipped) — RULED 2026-11-17: refused; S-02-D rewritten above.** D-20 relies on `update_service` refusing a set with an IPv6 backend before any write. Today: the host refuses (`BackendEntryPod::from_backend` returns `LoadFailed`); the `Dataplane::update_service` rustdoc says an IPv6 backend is "silently skipped" from the reverse-NAT key set; `SimDataplane` follows the rustdoc and accepts the set; and the existing sim test S-02-D (`sim_dataplane_reverse_nat_per_proto.rs`) asserts that. The new refused-IPv6 contract and equivalence tests follow D-20 (refused, prior read unchanged); they will force the sim and its S-02-D test to change, and the rustdoc to be reconciled. DESIGN must rule which stands.
- **B-D20-3 (hydrator unit tests).** Handoff item 4 and two mutants need `ServiceMapHydratorState.actual` as `BTreeMap<ServiceId, BackendSetFingerprint>`; the dispatch said to wire nothing into the hydrator's diff. Ruling needed: change the state type now as a scaffold (a mechanical rewrite of the receipt arms of `reconcile`, which changes behaviour) or leave item 4 to DELIVER with the type change.
- **B-D20-4 (no host failed-read injection).** Handoff item 2 asks for "a failed read is `Err`" on the host at Tier 3. A failed host read is an `ENOENT` on a freed inner map id, which the commit guard prevents and the appliance cannot produce; no safe injection point exists and inventing one adds production surface. The clause has no test on either adapter (the sim's scripted read failure was removed with it); the mutant "host read returns `Ok(empty)` on a failed read" has no test.
- **B-D20-5 (XDP slot test precheck), resolved by a one-time mutant run, 2026-11-17.** The production hash `fnv1a_5tuple_slot` is private to the BPF program, so there is no host-side precheck. The program computed `h % (INNER_TABLE_SIZE + 2)`, the BPF object was rebuilt, and `xdp_never_selects_the_two_fingerprint_slots` failed: `249 of 250 flows forwarded for source ports 12274..12524 (11499 forwarded so far)`. After the revert and rebuild it passed again. With today's flow set and hash, the test catches a modulus that reaches the two fingerprint slots. If the hash or the flow set changes, the run must be repeated.
