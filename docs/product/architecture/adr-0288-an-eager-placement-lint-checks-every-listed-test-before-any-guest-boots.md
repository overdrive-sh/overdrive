# ADR-0288 — An eager placement lint checks every listed test before any guest boots

## Status

**Approved by the user, 2026-11-14 (U-1), including the fixture-existence
extension; independent DESIGN review pending.** DDD-3 in the feature delta.

## Context

The wrapper refuses an unplaced test only when it runs on the Metal box, one
test at a time. A new or misspelled placement should fail in a lane the
engineer already runs, before any guest boots.

## Decision

A new `cargo xtask placement-lint` lists the workspace's tests with
`--features integration-tests,kvm-tests` and applies the wrapper's own
resolution to every one (through `test-wrapper.sh --check-placement`, so one
parser reads the record). It reports an unplaced test, a binary that mixes the
binary default with a non-host-pure record, and a lane fixture that is not a
listed test of the binary that provides it. It is wired into CI and pre-push
beside `dst-lint` and `conformance-lint` and writes nothing. The wrapper's
refusal stays as the last line of defence at run time.

## Alternatives

- **An xtask acceptance test that shells nextest**: a nested cargo inside a
  test, which the guest-kit rules forbid for lock contention; rejected.
- **A syntactic scan of test sources**: misses tests generated by `proptest!`,
  `quint_test` and similar, and cannot see the linker dropping a record;
  rejected.

## Consequences

A second reader of the record exists only as the wrapper's reader invoked by
the lint. The lint needs the test binaries built with both features, which the
CI `integration` job already does.
