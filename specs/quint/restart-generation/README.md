# Restart generation protocol

Feature `node-local-persistent-volume` (GH #348), three decisions, one hazard each: **SD-6** (ADR-0335, amends ADR-0073; approved 2026-11-18): a restart generation is handled when its successor is **observed** (the allocation issued for it has a row), never when it is emitted; **ADR-0337**: a pre-driver failure writes a charged `Failed` row (a Job's is final, RA11); **ADR-0338**: an admission refusal at the guest-network cap writes no row and charges nothing. The split from `specs/quint/node-local-volume/` is user ruling A (2026-11-18); the one scenario-to-run table is in `docs/feature/node-local-persistent-volume/feature-delta.md` § "Formal protocol model" and is not repeated here. The budget abstraction is user decision R-1 = option A (2026-11-18). The model has **no lane signal** (user ruling 2026-11-19): for the generation rule a launch superseded by a stop, a restart or shutdown and a launch lost with the control plane are identical (no row, no charge), so both are the one environment event `LaunchLost`; the signal and its shutdown are the volume spec's.

## Abstraction

`restart_generation.qnt`, module `restart_generation`, is the state machine (`init`, `step`). One node, one workload (`replicas = 1`), `NA` allocation ids (each minted once). It models `WorkloadLifecycle`'s restart rules over abstract launches: no volume, no claim, no VMM.

| Owner | Modelled as |
|---|---|
| launch | **one held dispatch.** `WlStart(a)` issues allocation `a` (the evaluation's tick: the lane opens, the View records the issued id); the allocation is `PENDING`, which stands for "a launch holds the lane" (production writes no row before the dispatch resolves). One later action resolves it, chosen by the environment flags at that instant, in the shim's order: **admission, then identity issuance, then the driver, which observes the lane signal**. `LaunchRefused` (`capFull`: no row, no charge), `LaunchPreFail` (`not capFull`, `idFault`: a `Failed` row), `LaunchRunning` (no flag), `LaunchStartFail` (no flag: a `Failed` row, any typed start failure including the volume's); the flags toggle freely, so every interleaving of a flag change with a launch is reachable. **`LaunchLost(a)`** is an environment event, enabled only when `OPS` contains `"lost"`: a `PENDING` allocation becomes `FAILED` with `W_LOST`, no row, no charge. Its guard is `not(capFull)` and `not(idFault)`, the shim's order (admission, then identity issuance, then the driver observes the supersede signal); `CpCrash` and `NodeReboot` still lose a launch at any moment. A restart commit enables the loss but does not force it. It has no fairness and is outside `Progress` |
| rows | `hasRow(a)`: an allocation row exists for `a`. A `PENDING` allocation has its `Pending` row (ADR-0353), a lost or superseded launch (`W_LOST`, state `ABANDONED`) its terminal row (ADR-0355: `Terminated`, `terminal: None`, reason `LaunchSuperseded` or `LaunchLostWithControlPlane`), and a pre-launch failure (`W_PREFAIL`) its `Failed` row; only a refused launch (`W_REFUSED`, admission, before any row is written) has **no row**. `ABANDONED` is a terminal, restartable, uncharged class that is not a natural exit: the relaunch carries its `cnt` unchanged (`startCnt`), it is exempt from the restart ceiling (`mayRestart`) and it is never `exhausted`; after a stop nothing is relaunched; a Job's abandoned row is relaunched (a launch that never ran is not a finished Job). `curA`: the highest id with a row (production `current_alloc`) |
| generation | `dg`: the committed desired generation (`workloads/<id>/generation`); `OpResume` and `WorkloadRestart` bump it (`dg < DGMAX`). `ig[a]`: the generation allocation `a` was issued for (the View's `issued_generation`). `pendingGen`: `ig[curA] < dg`, true only once a current row exists. `vetoed`: the current row was ended by an operator stop or restart and no generation is pending. `og`: a marker **no production rule reads**, written and read only by the hazard |
| restart budget (R-1 = A) | the per-allocation count `cnt[a]` (the View's `restart_counts` at issue): 0 for a first placement, the failed predecessor's `+ 1` for a crash restart, the predecessor's **unchanged** for a generation replacement. `charged(s)` and `exhausted(s)` are **derived**: `charged = cnt[curA] + 1` when the current row is `Failed`, `cnt[curA]` otherwise, `0` with no row; `exhausted = charged >= LIMIT` with nothing in flight. A lost or refused launch has no row and changes nothing. **`LIMIT` is production's ceiling plus one**: production restarts a failed row iff its count is below the ceiling, so a chain fails ceiling + 1 times; the model counts failures including the current row |
| workload-lifecycle | `canStart`: declared, not stopped, nothing `PENDING` or `RUNNING`, the lowest unminted id, not `vetoed`, and `charged < LIMIT` or a generation pending (a `workload restart` is a generation replacement, admitted whatever the attempt count). `WlStart` adds `not(capFull)` (the occupancy check at hydration). `StopAlloc` (a `Running` allocation that is stopped or whose generation is pending; `W_RESTART` when pending, else `W_STOP`), `WorkloadRestart` (a `Running` allocation ends; a `PENDING` one only bumps the generation; a `Failed` current row keeps its row and the generation becomes pending) |
| workload kind (H1, ADR-0335 item 3) | the constant `JOB: bool` of the main (not a state variable: a state variable would multiply `rg-safety-tlc`); `false` in `rg_ok`, `rg_conf`, `rg_live_*` and the hazard, `true` in `rg_conf_job`. `jobTerm(s, a)` (derived): `JOB`, a row exists for `a`, and its state is `TERMINATED` or `FAILED` (every ended Job row carries a terminal claim). `pendingGen` is false against a finished Job row; `canStart` additionally requires no current row (`curA == 0`: a Job is placed once, so no crash or failure restarts it, and **a pre-driver `Failed` row ends the Job**: RA11). `JobExit(a)` (environment, `JOB` only, a `RUNNING` allocation): the row becomes `TERMINATED` with `W_DONE`, the Job that ran to completion; it carries no fairness (no temporal property runs with `JOB`). `WorkloadRestart` has a fourth branch (`JOB`, `TERMINATED` current row): it only bumps `dg`. A `workload restart` of a running Job ends it (`W_RESTART`) and leaves it down, as on `main` (ADR-0335 item 3; #301) |
| environment (faults draw on `FB`) | `VmmCrash` (a `Running` allocation fails), `CpCrash` (every `PENDING` launch ends `ABANDONED`, `W_LOST`, at the boot step, `converge`'s first step; a `Running` allocation stays `Running`), `NodeReboot` (as `CpCrash`, and a `Running` allocation fails); `LaunchLost` (above, no fault budget); `IdFaultOn/Off` (SVID issuance fails or a non-start driver error), `CapFill/Drain` (the pool at its cap); `idFaultHeld` makes the identity fault true from init |

`conf_step` is **model-only**: it records the action taken so the conformance driver can replay it; it is never projected or compared. `stopped` stays projected (`desired_to_stop`). The projection of a row-less id separates `PENDING` from `W_LOST` by the held tick's completion (feature delta § Observable projections); the spec needs no change for it.

Not modelled, each with its reason:
- the volume, the claim wait, the boot wait (one start-failure class, `W_STARTFAIL`), the lane signal and node shutdown (the volume spec's: here a superseded launch is `LaunchLost`), orphan VMMs (RA5), backoff time, the guest-network pool beyond the boolean `capFull`: other specs or abstractions own them;
- `WorkloadRestart` on a `Terminated` current row of a service or with no row (it only bumps `dg`; no rule reads the difference). For a Job the `Terminated` row is the H1 branch above;
- **platform reclaim**: a reclaimed row has no terminal, is exempt from the restart ceiling and is restarted. The spec models no VMM and no reclamation sweep, and reclaim changes `restart_decision`'s budget test, not how a generation is handled, which reads the row's issued generation;
- **the `Stopped{SystemGc}` fresh placement**: a SystemGc-stopped row is neither vetoed nor restartable and falls through to a fresh placement. It arises only when a workload's intent is withdrawn, and workload deletion does not exist (GH #211), so no production path produces it;
- **a same-spec re-deploy**: `submit_workload` of identical bytes is `Unchanged` and bumps no generation, and a different spec at the same id is `409 Conflict` (`handlers.rs:524-554`, `:598`), so a re-deploy is a no-op for every rule modelled here.

## Decision, invariant, hazard

| Decision | Rule modelled | Invariants / properties | Hazard (`OFF`) and check |
|---|---|---|---|
| SD-6 (ADR-0335) | a generation is handled when the allocation issued for it has a row; a lost launch leaves it pending, the operator-stop veto does not fire while one is pending, the relaunch carries the predecessor's count | temporal `RunIntentProgress` (intent says run, the node is up, nothing blocks it and nothing is in flight: a launch is eventually issued); the runs | `stampOnEmit`: `og = dg` at `WlStart`, `pendingGen` reads `og`; `rg-hazard-stamp-on-emit` violates `RunIntentProgress`. Since ADR-0355 a lost or superseded launch leaves an abandoned, restartable row, so its counterexample is a launch refused at admission (`capFull`, no row, ADR-0338), the one launch that still ends with no row: the replacement launch is issued (`og = dg`), the pool fills, the launch is refused, no generation is pending and the operator-stop veto holds. The positive counterpart is `rg-live-replacement` |
| SD-6, finished-Job clause (H1, ADR-0335 item 3; RA11) | a finished Job row never has a generation pending, and a Job is placed once, so a restart of a finished Job issues no id and any row, a pre-driver `Failed` row included, ends it | `I_FINISHED_JOB_ISSUES_NO_ID` (in `Safety`, vacuous for `JOB = false`); the runs `restart_of_completed_job_does_nothing_and_issues_no_id` and `resume_of_stopped_job_does_nothing_and_issues_no_id` on `rg_conf_job` | none: H1 is a clause of the one SD-6 decision, and no exhaustive check runs with `JOB = true` (user ruling 2026-11-19) |
| ADR-0337 | a pre-driver failure (identity issuance, a non-start driver error) writes a charged `Failed` row, so a Service ends in `BackoffExhausted` with bounded ids | temporal `PreFailExhausts` (a declared workload under a persistent identity fault is eventually exhausted; ids minted `<= LIMIT + dg`) | `prefailNoRow`: `hasRow` also excludes `W_PREFAIL`, so nothing is charged and an id is issued per tick; `rg-hazard-prefail-no-row` violates `PreFailExhausts`. The positive counterpart is `rg-live-prefail` (kept: it is the holding side of this hazard) |
| ADR-0338 | an admission refusal writes no row and charges nothing, so a node held at the cap never exhausts a healthy workload's budget | `I_CAPACITY_WAIT_NEVER_EXHAUSTS` (`Safety`): `exhausted` implies the current row ended by a charged cause (`W_CRASH`, `W_STARTFAIL`, `W_PREFAIL`) | `refusalCharged`: `hasRow` no longer excludes `W_REFUSED`; `rg-hazard-refusal-charged` violates `I_CAPACITY_WAIT_NEVER_EXHAUSTS` |
| ADR-0355 | a launch that ends before running (superseded, or lost with the control plane) ends its `Pending` row with an abandoned `Terminated` row that names why: `LaunchLost`, `CpCrash` and `NodeReboot` take every `PENDING` allocation to `ABANDONED` at the boot step; the row is restartable, uncharged and carries its count to the relaunch | temporal `RunIntentProgress` (a dead `Pending` row would strand the workload); the runs `control_plane_crash_during_restart_launch_relaunches_once` and `second_restart_loses_launch_then_one_placement` pass through `ABANDONED` | `abandonWritesNoRow`: the row stays `PENDING` (and nothing resolves it, `dead`); the dead row blocks every placement and the workload is never relaunched; `rg-hazard-abandon-writes-no-row` violates `RunIntentProgress` |

`Safety` is `I_FINISHED_JOB_ISSUES_NO_ID` and `I_CAPACITY_WAIT_NEVER_EXHAUSTS`. `rg-safety-tlc` and `rg-live-replacement` are `ci = true` (each under two minutes).

## Assumptions (RA1, RA2, RA4 to RA11)

| Id | Assumption | Discharged by |
|---|---|---|
| RA1 | the outcome set is exhaustive: every `Err` and early return of the two dispatch arms is one of the launch resolutions or a named no-row outcome | the feature delta's launch-outcomes table and its code citations; shim tests of obligation 3a |
| RA2 | a launch in flight is invisible to a later evaluation, so `canStart` requires no `PENDING` allocation and one generation is never launched twice | lane exclusivity and the dispatch awaited inside the tick (ADR-0102, `reconciler_runtime.rs:1557-1628`); the seeded invariant `restart_generation_is_placed_exactly_once_across_supersession_and_crash` |
| RA4 | a lost launch (superseded by a stop, a restart or shutdown, or lost with the control plane) delivers nothing: an uncharged abandoned row (ADR-0355), no `Running`, no `Failed`, no budget input, no VMM | the volume spec's `I_SUPERSEDED_LAUNCH_DELIVERS_NOTHING`; the shim test of a superseded restart successor |
| RA5 | no VMM survives to block a placement (a booting orphan is reclaimed before any launch; a `RUNNING` orphan holds a non-terminal row) | the volume spec's M7 and the DISTILL test `boot_reclamation_ends_a_mid_boot_vmm_before_any_launch_for_its_workload` |
| RA6 | a launch failure caused by the volume (unavailable, held, `ensure` failure) is one typed start failure that writes a charged `Failed` row | the volume spec's typed-failure runs and the volume launch tests |
| RA7 | `LaunchPreFail` and `LaunchRefused` have the production order and effects of the table | shim tests of the pre-driver paths and of the refusal; `guest_network.rs:541-591` |
| RA8 | after `CpCrash` or `NodeReboot` the View, the intent and the observation rows survive and the runtime is rebuilt with a new lane table | ADR-0035 (View persistence), `vm_reclamation_boot::converge` before the loop |
| RA9 | the budget abstraction (R-1 = A): the model carries production's per-allocation count and derives `charged` and `exhausted`, with `LIMIT` = the production ceiling + 1 (`workload_lifecycle.rs:51`, `:408`, `:465`, `:1311-1318`) | the conformance driver compares `cnt` through `attempt_index_for_alloc` and `exhausted` through the rows; the run `generation_replacement_forgives_predecessor_failure` |
| RA10 | a Job row with a terminal claim is never replaced: the generation is not pending against it, matching the action shim's `allocation_attempt_transition` | the pure property asserting the two predicates equal over generated rows; the Job dimension of the seeded invariant; the two `rg_conf_job` runs |
| RA11 | a Job's failure before the driver is final: production finalises any ended Job row (`workload_lifecycle.rs:1091-1113`; natural exit through `is_natural_exit` `:1757-1775` and `classify_natural_exit_terminal` `:1781-1794`) and places a Job only while it has no row. The one production path that re-drives a Job row is a platform-reclaimed row (`is_natural_exit` excludes it, `:1775`), which the spec does not model; a pre-driver failure of that re-drive's successor is final in the same way | the `JOB` conjunct of `canStart` (`curA == 0`) and `I_FINISHED_JOB_ISSUES_NO_ID` model it; the Job pre-driver case of the seeded invariant and the shim tests |
